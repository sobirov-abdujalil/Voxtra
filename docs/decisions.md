| 2026-09-22 | Deploy platform: Render vs Fly.io vs Railway | Render (free tier) as the deploy target. Justification: long-lived Node process with outbound WebSocket to `wss://agents.assemblyai.com` (no serverless timeout to kill token-mint or idle sessions), public HTTPS by default (mandatory — `getUserMedia` needs a secure context), env-var secret injection for `ASSEMBLYAI_API_KEY`, automatic TLS with no cert management, and Git-based redeploys via `render.yaml`. Fly.io meets the same bar but needs `flyctl auth` on this machine; Railway needs a card after trial. Vercel-style serverless explicitly rejected: cold-start/function-timeout model cannot own a long-lived voice process and would split API/web into separate origins (CORS surface). | `render.yaml` (build `npm install && npm run build --workspaces`, start `npm run start --workspace=server`, health check `/healthz`); `docs/deployment.md`; user chose Render 2026-09-22 |
| 2026-09-22 | Deploy observability: /metrics vs logs | No public `/metrics` endpoint. In-memory token counters (`tokenHits/tokenSuccess/tokenFailure` in `app.locals`) plus one-line access logs (method, path, status, latency) and token-mint success/failure lines give deploy-time signal via platform logs with zero new dependency and zero secret exposure. | `server/src/app.ts` counters + logging; `server/tests/deploy.test.ts` asserts increments without leakage |
| 2026-09-22 | Deploy dependencies | No new dependency. Justification: same-origin static serving uses the existing `express.static`; health, logging, and counters are stdlib + Express only.
